## What was built

- `extensions/subagents/src/picker-trigger.ts` — the pure INV-20 decision module:
  - `shouldOpenPicker(input)` → `true` only when `editorText === ""` (exact empty,
    not trimmed), `autocompleteOpen === false`, `historyActive === false`,
    `runningCount >= 1` (finite number), and `enabled !== false`. Malformed input
    (`null`, `undefined`, non-object, non-finite/string `runningCount`) → `false`,
    never throws.
  - `resolvePickerEnabled(settings?)` → `true` unless
    `workflow.subagentPicker.downArrow === false`.
  - Zero imports; no TUI, no I/O, no rendering. Single decision point for INV-20.
- `extensions/subagents/picker-trigger.test.ts` — 8 focused tests covering all 9
  acceptance criteria at the pure-module seam.

Note on `enabled`: implemented as `enabled !== false` (fails open) to match
INV-20's "kill-switch not `false`" wording; a missing `enabled` field does not
silently disable the trigger. Documented in the module comment. PI-34 will feed
the boolean result of `resolvePickerEnabled` in, so the open case is nominal.
