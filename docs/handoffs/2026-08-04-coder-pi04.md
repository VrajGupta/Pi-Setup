# Handoff — coder, PI-04 (2026-08-04)

## What was built

PI-04 — adaptive persistent footer with live planner–reviewer stage rows.

- `extensions/ui-customization/footer.ts` (new, pure): `renderFooter(state) => string[]`,
  plus `columns` (moved here from `index.ts`, re-imported there for the header).
  3 base lines always; one row per stage-tagged agent sorted planner→reviewer, capped at
  `MAX_STAGE_ROWS = 4`; helpers (no `stage`) omitted. Row:
  `<glyph> <stage> <backend>/<model> · <elapsed> · <turns>t · <percent>` — percent only
  when the reading is `measured`; stale readings get a leading `~` and `dim` (INV-5).
  Row building is wrapped in try/catch: a throwing `readingFor` returns the 3 base
  lines (INV-6). No `node:` imports at all in the module (INV-3).
- `extensions/ui-customization/index.ts`: footer body extracted into the
  `renderFooter` call; `readingFor` builds via `buildReading` with source `context`
  from the summary's `contextTokens`/`contextWindow` (measured when both present,
  indeterminate otherwise, carrying elapsed/turns). Readings are stamped with
  `agentsAt` = epoch ms of the last `SUBAGENT_STATE_CHANNEL` publish, so a quiet
  bus renders rows stale instead of falsely fresh.
- `extensions/ui-customization/footer.test.ts` (new): 14 tests, one per acceptance
  criterion plus ordering, elapsed clamping, status-line append, perf, and the
  no-I/O source assertion.
