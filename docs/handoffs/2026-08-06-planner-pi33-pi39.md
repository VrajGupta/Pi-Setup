## Decisions locked (Vraj, 2026-08-06)

1. Replicate the UX in Pi only; Claude Code itself is out of scope for this repo.
2. Trigger = **both** a guarded `CustomEditor` subclass for true bare DOWN **and** an
   `alt+down` always-works alias, plus a `workflow.subagentPicker.downArrow` kill-switch.
3. Trigger fires when **≥1 subagent is `running`**; the picker lists **all** subagents,
   running first, then done/failed.
4. Picker includes stage agents and helpers. DOWN only **opens** a view; sending still
   requires PI-17's explicit in-view send affordance.
5. Escape from a subagent → picker; escape from the picker → main session.
6. The **belowEditor** surface is the one that becomes unbounded. The **footer keeps its
   7-line INV-4 cap, unchanged**.
7. `workflow.statusWidget.maxLines: 0` = unlimited, bounded only by terminal height with
   rows reserved for editor + footer; overflow collapses to `+N more · /flow`.
8. Content = this repo's **active** tickets as rows; done counted in the rule line only;
   cross-repo stays in `/flow`.

## Why the trigger is an editor subclass and not a keybinding

`pi.registerShortcut` is checked **first** in the editor input path and **unconditionally
swallows** a matching key — the handler cannot decline (`custom-editor.js:26`,
`interactive-mode.js:1400-1411`). Binding bare `down` would permanently destroy cursor-down,
move-to-line-end, and prompt-history-forward (`pi-tui/components/editor.js:678-689`).
`ctx.ui.setEditorComponent` is the only API allowing a *conditional* intercept, and
`CustomEditor` is a public export whose subclasses the runtime auto-populates with every
app-level handler and the autocomplete provider (`interactive-mode.js:1855-1895`).

## Invariants

- **Unchanged:** INV-2, INV-3, INV-4 (footer clause — the 7-line cap and `footer.test.ts`
  bounds are **not** relaxed), INV-6, INV-8, INV-10, INV-11, INV-13.
- **INV-4 second amendment** — `maxLines` is a configurable runaway guard: `0` = unlimited,
  any other value clamped `[8, 200]`, absent/non-numeric = 40. Width safety, deterministic
  line count, and lossless truncation clauses unchanged.
- **INV-19 (new)** — the status surface never occludes the prompt. Emits at most
  `max(0, terminalRows − reservedRows)` lines; this bound beats `maxLines`, including
  unlimited mode; truncation ends in exactly `+N more · /flow`; below the minimum it emits
  nothing. `terminalRows` is captured off render (INV-3).
- **INV-20 (new)** — the DOWN trigger never steals navigation and never sends. Intercepts
  only when buffer empty + autocomplete closed + not mid-history-nav + ≥1 running +
  kill-switch not `false`; otherwise delegates byte-identically. No keystroke path may
  deliver text to any subagent. Extends PI-11 / INV-8.
- **INV-14 (extended)** — the 50 ms / 200-ticket render budget now also holds with
  `maxLines: 0`.
