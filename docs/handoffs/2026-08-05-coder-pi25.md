## Scope

Every `/mode` switch persists to `settings.workflow.mode` via the existing settings mechanism — no new I/O layer.

- Created `extensions/workflow/settings-mode.ts` with `persistWorkflowMode(mode, settingsPath?)` and `readWorkflowMode(settingsPath?)`.
- `persistWorkflowMode`: read → parse → merge `workflow.mode` → temp-write → rename (atomic). Preserves every other key. Returns `false` on failure.
- `readWorkflowMode`: read settings, return persisted mode or `"workflow"` default. Missing/invalid/non-object → `"workflow"` (INV-6).
- Hooked into `/mode` handler (both pick and direct-switch paths): mode switches in-session, then `persistWorkflowMode` is awaited. On failure, notification shows `· session only` at `warning` level.
- Startup already reads `workflow.mode` from settings via `readGlobalSettings` → `modeFromSettings` — unchanged, works with persisted value.

## Invariants held

- **INV-2** (secret redaction): only `workflow.mode` is read/written/logged — a closed two-value enum. No credentials, URLs, or tokens pass through.
- **INV-6** (throwing getters degrade): `readWorkflowMode` returns `"workflow"` for missing/invalid/malformed settings. `persistWorkflowMode` returns `false` on failure, never throws.
