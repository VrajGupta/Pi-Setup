## Debugger findings and fixes

The red-team pass exposed and fixed four classes of issues:

1. Installer robustness. Repeated installs in the same second could collide while backing up `node_modules`; malformed JSON was previously treated as an empty object and overwritten; and installing with `PI_CODING_AGENT_DIR` equal to the repository could move the source resources it was meant to install. The installer now validates settings before mutation, migrates `steeringMode: "all"` to `"one-at-a-time"` atomically, uses collision-safe backup names and staged links, and treats source-equals-target installs as no-ops. Tests cover paths with spaces, four same-second runs, malformed settings preservation, and in-place repositories.

2. Orchestrator boundary. The workflow extension has no generic input handler or UI input capture for stage steering. The only stage relay is the explicit orchestrator `workflow send` path; it rejects blank text and non-active-stage IDs. Helpers remain on the helper-specific path. The stage prompt and README/SYSTEM/SETUP language now match that boundary.

3. Honest telemetry. Claude occupancy rejects negative/non-finite/malformed per-request token fields and reports zero as unknown. Unknown context strings omit `%`; measured readings strictly between 0% and 1% render `<1% ctx`. Existing footer, flow-panel, and context-utilization regressions cover the display contract.

4. UI affordance. The rendered header/footer paths contain no visible `STEER` affordance. `canSteerStage` is absent from implementation code. The regression assertion mentioning that removed symbol is confined to the policy test.
