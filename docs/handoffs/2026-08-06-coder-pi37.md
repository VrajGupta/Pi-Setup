## What was built

- `extensions/ui-customization/status-widget.ts` —
  - `normalizeMaxLines` exported; `0` now yields the unlimited sentinel
    (`Infinity`), any other numeric value clamps to `[8, 200]`, absent/non-numeric
    yields default 40. The render path's existing `lines.length <= maxLines` early
    return emits every deterministic line with no `+N more` line in unlimited mode.
  - Module stays pure (no fs/network/subprocess); existing source-purity test
    unchanged and green.
- `extensions/ui-customization/status-widget-settings.ts` (new) —
  - `resolveStatusWidgetMaxLines(settings)` navigates
    `workflow.statusWidget.maxLines` safely; non-object shapes and throwing getters
    normalize to 40 (INV-6).
  - `readStatusWidgetMaxLines(settingsPath?)` reads the agent settings file
    (`getAgentDir()/settings.json`), catches every failure → default 40, never
    throws (INV-6). Settings path injectable for deterministic tests.
- `extensions/ui-customization/index.ts` —
  - `uiCustomization(pi, options)` gains an optional
    `{ readStatusWidgetMaxLines?: () => number }` seam (defaults to the file
    reader) so wiring tests are deterministic and never touch the real settings
    file.
  - The `vraj-status` widget factory resolves `maxLines` **once per widget mount**
    (off the render path, INV-3) with a try/catch fallback to the default, and
    passes it as plain state into `renderStatusWidget` (replacing the
    `maxLines: undefined` call-site bug).
  - `renderStatusWidget` itself still performs no settings read (INV-3).
