### BUG-1 (blocking, invariant + data loss) — five historical tracker records deleted to satisfy a magic number

The candidate deleted the `PI-01`–`PI-05` sections from `tickets.md` (196 lines), leaving exactly
34 records.

**Evidence that the deletion was unnecessary.** `HEAD`'s `tickets.md`, with all five sections
intact, parses **cleanly** under the candidate's own new strict parser:

```
tickets-HEAD.md   reason=undefined  records=39  {"done":38,"dropped":1}
candidate         reason=undefined  records=34  {"done":34}
```

No validation error, no malformed status, no duplicate ID. The only thing the deletion bought was
`assert.equal(headings.length, 34)`.

This directly violates the ticket. AC2: *"Do not hard-code `34` … the renderer must derive counts
and rows from the validated snapshot"*. AC8: *"no new fake issue is added just to make the count
match"* — deleting five real completed records to hit a target is the same failure mirrored.
`PI-01`–`PI-05` are genuine completed work (four `Done`, `PI-03` `Dropped`) that predates the
GitHub board and therefore has no issue number; the 34 figure is the count of *board-mapped*
tickets (`PI-06`–`PI-39`), not the count of tracker records.

**Fix.** Restored all five sections verbatim from `HEAD`. Kept the coder's corrected
canonical-source header prose and made it accurate: the file mirrors the board and additionally
retains the pre-board local history, which is never deleted to make a count line up.

### BUG-2 (test quality) — counts pinned to 34 in two places

- `ticket-snapshot.test.ts` asserted `headings.length === 34` and `done === 34` against the **live**
  `tickets.md`. Rewritten to assert derivation: records match headings one-for-one, IDs are unique,
  pre-board and board-mapped history both survive, `PI-28`/`PI-31`/`PI-39` are `done`, and no
  `review-ready` record remains.
- `status-widget.test.ts` built the AC1/AC2 "baseline readback" by parsing the live tracker and
  asserting 34. Replaced with an **explicit synthetic 34-record fixture** (which is what AC1 asks
  for — "a baseline fixture") rendering `0 active · 34 done`, plus a second assertion that adding
  one active record moves the rule to `1 active · 34 done`. That is the actual AC2 property: the
  count follows the records. A separate derivation-based check still exercises the live tracker.

### BUG-3 (the failing gate test) — empty repo identity expected to render a row

`legacy single-snapshot fallback…` asserted that a snapshot with `repo: ""` renders
`repo — · id PI-99`. The coder's validator correctly rejects an empty repo, so the test failed.

The **test** was wrong, not the code. An unattributable ticket must fail closed under invariants 3
and 4 ("a malformed … tracker degrades to a truthful bounded unavailable/error state rather than
displaying guessed rows"). Rendering a `—` placeholder for an unknown repository is precisely the
guessed row the ticket forbids.

Fixed test-first, and **without losing the redaction coverage that assertion carried**: the empty
repo case now asserts fail-closed *and* that `PI-99` never appears, while a second case with a
well-formed repo and hostile secret-bearing title asserts the row renders with secrets and
terminal-control bytes stripped (invariant 6).

### BUG-4 (format gate) — `ticket-snapshot.ts` indentation

`npm run format:check` failed. Fixed via `prettier --write`; now exit 0.

   the board's literal mirror, `PI-01`–`PI-05` need an explicit archival decision — made
   deliberately, not by deletion.
