## Findings and test-first fixes

1. **Registry path semantics.** Relative entries were returned verbatim and `~` was only expanded by the later read helper. The registry now resolves relative paths against the current repository fallback, expands `~`/`~/...`, normalizes absolute paths, and deduplicates after normalization. Regression covers relative and absolute/tilde entries without any directory scan.
2. **Timeout collision and cleanup.** A provider/read error with message `repository read timed out` was classified as a timeout because the implementation compared error text. The timeout now uses an opaque symbol sentinel. The timer is cleared after either race winner, while the read remains bounded at two seconds. Regression proves the colliding error is `unreadable` and the real pending read is `timeout`.
3. **Parse-empty health.** `parseTicketSnapshot` returns an empty snapshot with a reason for an empty tracker. The Issues view previously rendered a healthy zero-ticket repository. It now renders `unavailable — empty tracker` and no rows.
4. **Cross-repository ownership.** A snapshot or record could be displayed under a different repository header. Snapshot validation now requires the snapshot repository to match the enclosing read and record validation rejects records with a different repository. Both the multi-repo and legacy single-snapshot seams have mismatch regressions; the wrong ticket text never renders.
5. **Malformed view and stale cache.** A non-boolean `defaulted` field was silently coerced to false, and invalid view/read inputs could leave cached rows available. The view container now fails closed and invalid/empty/exception paths clear all derived caches. Empty reasons render the explicit `unknown` placeholder.
6. **Capture freshness.** Repository header staleness uses the older of the read and snapshot capture timestamps, so a fresh wrapper cannot make an old snapshot look current.
7. **Display boundary.** Added a production Issues-view probe for terminal controls, Authorization-shaped repository names, and secret-shaped title text. Repository names and ticket text remain redacted and terminal-safe; frame bounds remain enforced by the existing wrapper.

No unfixed PI-14 defect remains within the owned lane.
