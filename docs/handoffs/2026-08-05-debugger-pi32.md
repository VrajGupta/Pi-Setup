## Attack surface probed (all red-team probes, production seams)

1. **Startup:** `session_start` reads settings via `readGlobalSettings` (try/catch → undefined), `readRoutines` is throw-safe (`safeGet` per key), `startRoutineLifecycle` stops any prior lifecycle before creating a new one (clean double-start). No routines → `start([])` emits empty snapshot and creates no timer. Throwing settings read → routines `[]`, idle, no crash (INV-6).
2. **Shutdown:** `session_shutdown` calls `routinesLifecycle?.stop()` (stops scheduler, clears timer, emits empty snapshot) and sets the lifecycle to `undefined`. Shutdown without start is a no-op (`?.`). ui-customization's `session_shutdown` stops the `vraj:routines-snapshot` listener exactly once and clears `routinesSnapshot`. No leaked timers (scheduler `stop()` clears `timer`; lifecycle `stop()` clears `scheduler`).
3. **Settings refresh:** `/routine snooze|disable|enable` reads settings, applies update in memory, persists atomically, updates `configuredRoutines`, and calls `refresh()` (= `start`), which stops the old scheduler (clearing its timer) before creating a new one — no timer leak, no duplicate fire. Write failure → `· session only` warning; live scheduler still reflects the change.
4. **Snapshot producer:** `buildRoutinesSnapshot` is a pure reader of `scheduler.getSnapshot()` + definitions; never writes; skips null entries; `finiteNumber` guards non-finite `snoozedUntil`/`scheduleMs`/`lastFiredAt`; `dueAt` uses now for due, `snoozedUntil` for snoozed, `lastFiredAt + interval` estimate otherwise. The channel listener in ui-customization filters non-object entries (INV-6) and stays off the render path (INV-3).
5. **Banner wiring:** `onDue` → `ctx.ui.notify(routineBanner(name), "info")` — quiet, non-blocking, info severity; never auto-runs (INV-8); fires once per due event from the scheduler tick (interval/anchor gating in `isDue` prevents re-fire each tick). Banner text is terminal-safe via `displayText`.
6. **Docs:** `settings.example.json` has `"routines": []` under `workflow`. `SYSTEM.md` Routines section correctly states quiet banner, INV-8 classification, no bridge spawns. README.md has the full Routines section (commands, surface, scheduler semantics, example settings block).
7. **Regression:** 196 focused tests + `tsc --noEmit` + Prettier all exit 0.
8. **Missed corners:** disk-edit mid-session is out of scope (settings refresh only via `/routine`, per spec q2/q5); disable-all → scheduler creates no timer (`hasActive` false); snapshot-before-first-tick emits `dueAt` estimates; long routine names are width-truncated by the surface/panel; channel subscription is registered once at extension init; in-flight `onDue` settle after `stop()` cannot notify because `context` is cleared in `session_shutdown` before any async settle.

- **Docs acceptance criterion (real defect):** PI-32 requires `README.md` and `SYSTEM.md` to contain `routine`, `/routine`, and `classifyRequest`. `SYSTEM.md` had `classifyRequest`; `README.md` did not. Verified both files now contain all three literals.
  - Debugger diff SHA-256 (working tree vs c8902d4): `2ea861b45076518f104ebd32c388519dd474c8b81ca3430fdd5e898f4affb8f0` (README.md only, 2 lines).

**Rejected (probed, no defect):**

- `buildRoutinesSnapshot` does not catch a throwing `scheduler.getSnapshot()` — deliberate: the scheduler's `getSnapshot()` is a plain object access, and the lifecycle's `emit()` is the bounded seam; the existing PI-32 test pins the throw semantics.
- Completion list includes disabled/snoozed routine names — intentional: `/routine` completions are name completion; the bare picker filters to available routines.
- `stop()` emits an empty snapshot on every stop (including `start()`'s internal stop) — harmless ordering; widget renders the latest snapshot.
- Restart-on-refresh instead of in-place `setRoutines` — documented design choice because the read-only scheduler exposes only start/stop; stop clears the old timer so there is no leak (INV-18).
