## Attack surface probed

1. **Banner (INV-8, q3):** `routineBanner` produces quiet info banner with exact affordance tokens; no auto-run language; empty name safe; `displayText` redacts secrets.
2. **Bare `/routine`:** picker of enabled/not-snoozed routines; empty config → info line (`no routines configured`), no red error; cancel → no throw, no state change; whitespace args → same as bare.
3. **`/routine run <name>`:** routes via `classifyRoutinePrompt(prompt, mode)` → `classifyRequest(prompt, mode)` with the **current session `mode`** (not hardcoded); outcome surfaces through `setState` + `ctx.ui.notify` (same mechanism as `/mode`); unknown name → warning; `__proto__`/weird chars → safe (string comparison, no prototype pollution).
4. **`/routine snooze <name> [minutes]`:** `parseSnoozeMinutes` defaults 60, clamps [1, 10080]; invalid (0, -5, "abc", 1e9, NaN) → warning, no persist, no throw; unknown name → warning; write via `writeRoutines` (settings preservation); write failure → `persistSettingsFile` returns false → "session only" warning.
5. **`/routine disable/enable <name>`:** follows spec (disable/enable as subcommands of `/routine` per `/mode` pattern); persisted via `writeRoutines`; unknown → warning.
6. **Completions:** `routineCompletions` returns configured names; `getArgumentCompletions` prefix-filters; no duplicates (first-wins from `readRoutines`); empty config → empty.
7. **INV-3:** `routineBanner`, `normalizeRoutineCommand`, `applyRoutineUpdate`, `routineCompletions`, `classifyRoutinePrompt` — all pure functions; handler does settings I/O only via `readGlobalSettings`/`persistSettingsFile`.
8. **INV-6:** throwing `readGlobalSettings` → caught, returns `undefined`; `readRoutines` uses `safeGet` for throwing getters; command stays responsive.
9. **Regression:** `/mode` picker/warning/completions/prefix filter, `/flow`, all 40 flow-panel tests pass; `configuredRoutines` cleared on `session_shutdown` (closure variable, no timers in PI-30).
10. **Missed corners:** snooze on disabled routine (harmless — scheduler ignores disabled routines); run on disabled routine (explicit user invocation, no check needed per spec); name with leading/trailing spaces (handled by `trim()`); duplicate names (first-wins per `readRoutines`); banner+snooze interaction (PI-32 concern); clock rollback (acceptable — scheduler re-evaluates at next tick).
