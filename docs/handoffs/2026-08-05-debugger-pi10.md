## Red-team findings and fixes

1. **Blocker truth boundary.** A snapshot could claim `unblocked` while carrying an unsatisfied blocker, or `blocked` with no unsatisfied blocker. The validator now rejects those contradictory records. Duplicate IDs are rejected so a ticket cannot appear ambiguously or be rendered twice.
2. **ETA shape boundary.** Estimated ranges now require finite safe integer millisecond bounds and `n >= 3`; malformed/unsafe estimates degrade to `issue list unavailable — invalid snapshot`. ETA text remains direct PI-13 passthrough; the view does not estimate or mark staleness itself.
3. **Failure/cache boundary.** Derived rows cache by immutable snapshot identity, keeping repeated renders below the 2-second budget. Cache state is committed only after successful validation/render shaping and is cleared on getter/validation failure, so a malformed replacement cannot reuse stale rows.
4. **Display safety.** Added focused production-path probes for empty fields, malformed quoted assignment tails, AWS-style credential assignment, credential-shaped rootless URI text, terminal controls, and role vocabulary. Display output redacts these values and preserves explicit `—` / `eta unknown` placeholders. The view remains text/ASCII legible with the colourless test theme.

No in-scope defect remains. No changes were made to the shared PI-13 parser; its snapshot is treated as an untrusted runtime value at the view boundary.
