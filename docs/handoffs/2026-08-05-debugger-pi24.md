## Findings fixed test-first

### 1. `getArgumentCompletions` ignored its prefix (defect)

The coder's implementation `() => MODE_COMPLETIONS` always returned both `workflow` and `free` regardless of the argument prefix. The spec requires case-insensitive filtering: `("f")` and `("FR")` each return only `free`.

**Fix:** Changed to `(prefix: string) => { if (!prefix) return MODE_COMPLETIONS; const lower = prefix.toLowerCase(); return MODE_COMPLETIONS.filter((item) => item.value.startsWith(lower)); }`.

**Test:** Added `"/mode completions filter by prefix, case-insensitive"` in `flow-panel.test.ts` covering empty, `"f"`, `"FR"`, `"w"`, and `"x"` prefixes.

### 2. `policy.test.ts` regressions from PI-24 changes

Two test failures introduced by the coder's new `ctx.ui.select` picker in the `/mode` handler:

- **"main-chat input remains orchestrator-only"** — asserted `doesNotMatch(source, /ctx\.ui\.(input|select)\(/)` but the `/mode` handler now uses `ctx.ui.select` for the mode picker. **Fix:** Split the assertion to check only `ctx.ui.input(` for routing, with a comment that `ctx.ui.select` is used by the `/mode` picker, not for routing.
- **"the mode command validates, changes only live state, and wires every route seam"** — mock context lacked `ctx.ui.select`, causing bare `/mode` to throw `ctx.ui.select is not a function`. Expected notification types were `"error"` but PI-24 uses `"warning"`. Expected notification text was `"routing mode: free"` but PI-24 uses `"mode free (manual)"`. **Fix:** Added `select() { return undefined; }` to mock; split the invalid loop into bare-mode (cancelled picker → no notification) and invalid-value (warning notification); updated expected notification type and text.

## Findings rejected (no defect found)

- **Bare `/mode` → picker cancel:** handler returns early when `ctx.ui.select` returns undefined. No mode change, no notification, no throw. Verified both in code review and via the updated policy.test.ts.
- **White-space handling:** `/mode  FREE  ` → trimmed to `FREE` → lowered to `free` → valid switch. Verified in `normalizeModeCommand` and its tests.
- **Non-string args:** `typeof args !== "string"` → empty string → `{kind: "pick"}`. No throw.
- **INV-8 (no spawn/send):** The handler only calls `normalizeModeCommand`, `ctx.ui.select`, `ctx.ui.notify`, and `setState`. No spawn/send/delegate/fs/network path.
- **INV-2:** The mode handler only reads/writes the `mode` closed enum. No credentials, URLs, or tokens pass through.
- **`(manual)` label consistency:** `/mode` confirmation `"mode free (manual)"` matches PI-21's `modeLabel()` in `status-widget.ts`.
- **Repeated invocations:** `/mode free` → `setState({ mode: "free" })` → `/mode workflow` → `setState({ mode: "workflow" })` works correctly.
