## Findings fixed test-first

### 1. `getAgentDir()` default throws before try/catch (INV-6)
Both `persistWorkflowMode` and `readWorkflowMode` computed their default settings path via `settingsPath ?? join(getAgentDir(), "settings.json")` as a default parameter, which evaluates before the function body — a throwing `getAgentDir()` would propagate uncaught to the `/mode` handler, crashing the extension.

**Fix:** Path resolution moved into the try block. The `temporary` variable is declared `let temporary: string | undefined` outside the try block so the catch block can clean it up.

### 2. Concurrent write race (INV-12)
Two rapid `/mode` switches could interleave: handler 1 reads file, handler 2 reads the same file (before handler 1's rename), then both write — the last rename wins, and the file and live mode diverge. With `Promise.all`, both calls evaluate `await writeQueue` before either sets the continuation, so a simple `await writeQueue` guard is insufficient.

**Fix:** Module-level `writeInProgress` promise chain. Each call captures the previous call's promise (`prevWrite = writeInProgress`) before creating its own (`writeInProgress = new Promise(...)`), then `await prevWrite` waits for the previous write. This ensures concurrent calls (even through `Promise.all`) are serialized correctly.

### 3. No runtime guard on `persistWorkflowMode` (INV-12)
The typed `WorkflowMode` parameter is TypeScript-only; JS runtime could pass an unnormalized value.

**Fix:** Added `if (newMode !== "workflow" && newMode !== "free") return false` inside the try block.

### 4. Invalid persisted mode → no startup warning (INV-6)
A settings file with `workflow.mode: "WORKFLOW"` or `"banana"` silently defaulted to `"workflow"` without notifying the user. Both `modeFromSettings` in index.ts and `readWorkflowMode` in settings-mode.ts treated any non-"free" value as "workflow" without distinguishing valid from invalid.

**Fix:** Added `validateWorkflowMode(raw: unknown): { mode: WorkflowMode; warning?: string }` pure function that returns a warning string when the persisted value is present but not in `{"workflow", "free"}`. The warning never contains the raw value (INV-2). Wired into `session_start` to emit `ctx.ui.notify(warning, "warning")`. Replaced `modeFromSettings` usage with `validateWorkflowMode`.

### 5. Missing edge-case coverage
- Non-object `workflow` key (string, number) — handled gracefully
- `validateWorkflowMode` with every invalid value class
- Runtime guard rejection (`persistWorkflowMode("garbage")`)
- Concurrent write serialization (success and failure)
- `getAgentDir` failure resilience
