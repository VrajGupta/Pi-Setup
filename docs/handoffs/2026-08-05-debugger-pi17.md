## Audit and red-team findings

- Baseline focused suite passed; `npm run check` clean.
- **Dashboard still advertised `x abort` for a selected stage** while the abort
  action itself was disabled for stages (inconsistent affordance, INV-11).
- Stage rows in the dashboard rendered raw title/id/model/args without the
  terminal-safe + secret-redacted display path, so a hostile snapshot could
  inject control characters or leak credentials into the dashboard (INV-2).
- `TakeoverView` accepted input and rendered after `close()` (submit path,
  `handleInput`, and the send-error callback all lacked a closed guard), which
  could mutate a closed view or surface a stale error.
- Input render lines were not width-truncated, risking overflow at narrow
  widths (INV-4).

## Fixes

- Abort affordance matches behavior: `x abort` is only rendered/advertised for
  non-stage (helper) agents; the action itself is stage-guarded
  (`snap.stage === undefined`).
- Added `safeDisplaySnapshot`/`safeDisplayLine`/`safeDisplayText` so every
  dashboard and takeover surface renders sanitized + redacted text (titles,
  ids, prompts, cwd, model labels, session paths, transcripts, tool args/
  outputs, queued text, final text, errors).
- Closed-view guards on `TakeoverView.handleInput`, `onSubmit`, and the stage
  send-error callback; a closed takeover cannot mutate or surface stale errors.
- Input render lines are truncated to the viewport width.
- Minimal production-seam regressions added for stage abort affordance, closed
  view input, secret/control-char sanitization, and narrow-width rendering.
