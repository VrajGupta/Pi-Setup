## Scope

Hardened the PI-23 issue rows in `extensions/ui-customization/status-widget.ts` against INV-2 secret/control-char leaks, INV-6 per-record robustness, and INV-10 placeholder gaps.

## Findings

### Fixed

1. **INV-2 (secret redaction): assignee, id, status, blocker ids were unredacted.** Only `title` was passed through `safeToken`. Now every user-controlled cell is redacted: `safeToken(r.id, "?")`, `safeToken(issueStatusLabel(r.status), "?")`, `safeToken(r.assignee, "—")`, `safeToken(b.id, "?")` inside `blockerSummary`. Control characters (ANSI escapes, nulls, tabs) are stripped from all these cells.

2. **INV-6 (per-record isolation): one malformed record killed the entire issues section.** The `issueSection` catch caught the throw and rendered `"issues unavailable — render error"`, hiding all good records. Now each record's cell building is wrapped in try/catch inside `issueRows`; bad records are skipped (return null from map, filter out). Non-object records are filtered before `issueRuleLine`/`issueRows` enter.

3. **INV-10 (empty title placeholder): empty title rendered a blank cell.** `safeToken(r.title, "")` returned `""` for empty titles. Changed fallback to `"—"` so blank titles show an explicit placeholder.

4. **blockerSummary null guard:** `blockedBy.length` on null/undefined threw. Added `!Array.isArray(blockedBy) ||` guard returning `"blk none"` for non-array inputs.

### Rejected (within scope)

- **INV-4 truncation ellipsis on joined line:** Already handled by `truncateToWidth`'s default ellipsis `"..."` via `safeTruncate` in `layoutColumns`. No defect.
- **ANSI-laden status silently drops record:** The status `"\u001b[31mcoding\u001b[0m"` doesn't match `PIPELINE_ORDER`, so the record is excluded. With the `safeToken` fix, the status is sanitized before comparison, so it correctly matches. This is the correct behavior — the ANSI is stripped, and the record is shown.
- **Per-record isolation in `issueRuleLine`:** Addressed by filtering non-object records before the rule line computation. The rule line now safely counts only valid records.
