## Findings and fixes

- The rewritten baseline tests were green but weak: they did not prove timeout
  semantics, ten slow intervals, synchronous throws, malformed results, all invalid
  interval values, timer cancellation, unref behavior, settings, or poll purity.
- Timeout now records the exact `timeout` reason while preserving the last completed
  snapshot and its `capturedAt`; the in-flight flag remains set until the slow read
  actually settles, so a timeout cannot create an overlapping read.
- Synchronous throws, rejected reads, empty error messages, malformed snapshots, and
  reason-carrying reads now degrade to non-empty reasons without escaping the poll.
  A result from another repository cannot replace the current repository's records.
- `stop()` cancels both the recurring timer and an active read-timeout timer. Both
  timer classes are unref'd. Completion after stop cannot publish a new snapshot.
- Interval input is treated as untrusted runtime data and clamps to [2000, 300000],
  with 10000 for missing, non-numeric, NaN, or infinite values. The example settings
  now carries `workflow.trackerPollMs: 10000`.
- The module has no filesystem, network, subprocess, write, commit, or push path.
  Existing `issue-list.test.ts` evidence covers stale `~` rendering, unavailable
  repository isolation, width bounds, and render-path purity.
