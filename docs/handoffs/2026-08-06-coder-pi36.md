## What was built

- `extensions/workflow/tracker-poll.ts` — additive `onSnapshot` option on
  `startTrackerPoll`: called with the snapshot after every completed read
  (success or reasoned failure), so a consumer publishes without polling
  `getSnapshot()`. Existing behavior and options unchanged.
- `extensions/workflow/index.ts` —
  - `TICKET_SNAPSHOT_CHANNEL = "vraj:ticket-snapshot"` (exported, mirrors
    `ROUTINES_SNAPSHOT_CHANNEL`).
  - `readTrackerSnapshotForPoll(path)` maps the bounded `RepositoryRead` to the
    poll's `TicketSnapshot` shape (records on success; `records: []` + reason on
    failure).
  - `startTrackerPolling(pi, settings, cwd, options)` — resolves
    `workflow.trackerPollMs` (clamped by the poll to `[2000, 300000]`, default
    10000, INV-13) and the first declared repository from settings; emits every
    completed snapshot on the channel. Clock/timer/read injectable for tests;
    production path uses real clock, unref'd timers, bounded read.
  - `session_start` starts the poll (stopping any prior one);
    `session_shutdown` calls `stop()` and clears it.
- `extensions/ui-customization/index.ts` — listener on
  `vraj:ticket-snapshot`: shape-validates each published value
  (`asStatusWidgetSnapshotView`), stores it in `ticketSnapshot`, requests a
  render; malformed values leave the previous snapshot in place (INV-6). Snapshot
  reset on `session_start`/`session_shutdown`; listener removed on shutdown.
