## Findings and fixes

1. **Settled helper dashboard advertised an invalid abort action.** The hint only checked
   `stage === undefined`, so a `done`/`error` helper still displayed `x abort`, even though
   `handleInput` correctly refused to abort non-running snapshots. This was a UI contract
   defect: hint text was not truthful. Fixed the dashboard hint to require both
   `status === "running"` and no workflow stage; added a focused regression for settled
   helpers.
2. **Mutation-safety evidence was narrower than the contract.** The pure sorter already
   copied its input, but the rendered-dashboard test did not verify the live list remained
   in its original order. Added that assertion at the dashboard seam.
3. **No-send evidence at takeover entry was implicit.** The existing dashboard cancellation
   test covered no send, but the takeover round-trip test did not assert that entering a
   takeover from confirm leaves both send channels untouched. Added the assertion; no
   production send path was added.

No other real defect or follow-up was found. In particular, status rank is explicit
`running → done → error`, ties are `createdAt` then `id`, empty-list handling remains
caller-safe, selection uses ids rather than volatile row positions, and the takeover loop
retains the required Escape round-trip.
