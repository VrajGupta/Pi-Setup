## Built

- **Lifecycle wiring (`extensions/workflow/index.ts`):**
  - `createRoutinesLifecycle` — injectable `now`/`setTimer`/`clearTimer` (mirrors tracker-poll/routines-scheduler); `start`/`stop`/`refresh`/`snapshot`.
  - `buildRoutinesSnapshot` — pure, off-render, read-only `StatusWidgetRoutineRecord[]` per configured routine: name, schedule summary, enabled, snoozedUntil, dueAt (due→now, snoozed→snoozedUntil, else lastFiredAt+interval estimate). INV-10 producer never writes; INV-3 no I/O in render.
  - `session_start` starts the scheduler from `readRoutines()`; `session_shutdown` calls `stop()` (clears timer + state, INV-18). No routines → idle, no timer, no crash (INV-6).
  - `/routine` snooze/disable/enable call `routinesLifecycle.refresh(configuredRoutines)` — restarts the scheduler (stop clears the old timer, so no leak) and recomputes next-due. Design choice: restart rather than `setRoutines` because the read-only scheduler exposes only `startRoutineScheduler`/`stop`; documented in code comment.
  - `onDue` → `ctx.ui.notify(routineBanner(name), "info")` (quiet banner, PI-30 intent; never auto-runs, INV-8).
  - Snapshot emitted on `ROUTINES_SNAPSHOT_CHANNEL = "vraj:routines-snapshot"`.
- **Snapshot consumer (`extensions/ui-customization/index.ts`):** listens on `vraj:routines-snapshot`, filters non-object entries (INV-6), updates `routinesSnapshot`, refreshes widget. `session_shutdown` stops the listener and clears the snapshot.
- **Tests (`flow-panel.test.ts`):** 7 focused PI-32 tests — start emits snapshot + schedules timer; empty start idle; stop clears timers + emits empty; refresh recomputes (disabled no-fire, sibling fires); snapshot builder per-routine summary; undefined/null-safe; throwing scheduler → bounded throw; snapshot() side-effect-free.
- **Docs:** README.md (Routines section: commands, surface, scheduler semantics, example settings block) and SYSTEM.md (short Routines section: quiet banner, INV-8 classification, no bridge spawns). No new model map — existing sections untouched.
